# 项目范围与验收约定

## 已确认的目标

确认日期：2026-09-17。

Symocraft 是 Windows x64 单机体素游戏工程，继续使用 C++ 与 OpenGL，兼顾图形技术栈和游戏引擎技术栈，重点展示两者之间的数据流设计。

- 日常开发环境：CLion + MSVC + CMake。
- 优先级：尽快交付首个可玩版本，再进行深入架构重构及性能优化。
- 保留项目身份和现有玩法，不要求保留原有 ECS、内存管理或其他自研基础模块。
- 允许在有明确理由、迁移路径和验证方法的前提下替换基础模块，不为展示技术而堆叠抽象。
- 随玩家移动加载、卸载区块属于首个可玩版本之后的独立范围；当前只预留必要边界。
- 存档、联网、完整生存系统、通用编辑器和新一代图形 API 不自动进入当前范围。
- 按节点交付，由用户验收后进入下一节点；重要依赖替换、范围扩大或指标调整单独说明。

## 参考硬件

| 用途 | 配置 | 核实状态 |
| --- | --- | --- |
| 开发与主要调试 | AMD Ryzen 7 9700X、RTX 5070 Ti、64 GB 内存 | M0 已在本机核实 CPU、GPU、操作系统可见内存及驱动 |
| 第一版性能参考与第二台运行验收 | Y9000P，i7-12700H、RTX 3070 Ti Laptop、32 GB 内存 | 用户提供，尚未在该机器运行 |

参考笔记本不是已认证的最低配置。测试时记录供电、性能模式、混合显卡/独显设置、驱动、温度和实际 OpenGL 渲染设备。不能把台式机数据、限制帧率或减少 CPU 核心数等同于低配实测。

## 阶段与通过条件

| 节点 | 主要产物 | 通过条件 |
| --- | --- | --- |
| M0 现状基线 | 环境、原始构建/启动证据、范围、问题和依赖清单 | 能区分环境问题、已复现问题和静态风险，明确后续修复范围；不要求已经修复 |
| M1 可靠构建 | 目标级构建配置、CLion 接入说明、可复现命令 | 全新目录 Debug/Release 构建通过，选择的工具链明确，不依赖 IDE 隐含配置 |
| M2 首个可玩版本 | 运行包、操作说明、玩法结果与初始性能记录 | 基础玩法、资源定位、初始化/退出和 15 分钟连续游玩验收通过；严重问题不以“待优化”名义放行 |
| M3 架构与正确性 | 明确模块边界、所有权、可测试核心逻辑、模块文档 | 核心逻辑可无窗口测试，边界测试和已有玩法回归通过，关键资源生命周期明确 |
| M4 性能 | 同场景优化前后对照、可重复测量方法 | 在冻结的场景和配置下达到约定指标，不靠降低世界规模或画质隐性达标 |
| M5 稳定性 | 长时运行、重复启动退出与异常场景记录 | 连续至少 60 分钟无崩溃、卡死和无法解释的持续资源增长；异常情况可恢复或清楚退出 |
| M6 独立交付 | Release 发布包、技术文档、第三方通知、验收摘要 | 脱离源码和 IDE 可用，并在没有开发环境的目标机器验证运行依赖和资源完整性 |

M0 构建成功不自动使 M1 通过；M0 看到世界画面也不自动使 M2 通过。每个阶段有自己的范围和证据要求。

## 性能目标与测量约束

以下是实施方案中的初始目标，不是现有项目性能结论。正式基准在 M2 建立可重复场景后、M4 优化开始前冻结；若实测发现需要调整，应与用户重新确认。

| 项目 | 初始约定 |
| --- | --- |
| 机器 | 上述 Y9000P 参考笔记本，接电并记录性能及显卡模式 |
| 构建与画面 | Release、1920 x 1080，固定分辨率、世界规模、视距、渲染选项和运动路线 |
| 流畅度 | 目标稳定 60 FPS；预热后的 P95 帧耗时不超过 16.7 ms，P99 不超过 33.3 ms |
| 场景 | 静止观察、固定路线移动、连续方块编辑；首次加载单独测量 |
| 采样 | 性能测试关闭 VSync；正常游玩另行验收开启 VSync 的体验；建议每场景预热 60 秒、记录 180 秒、重复 3 次 |
| 必须记录 | 原始帧时间、CPU/GPU 耗时、首次可操作时间、网格生成/重建耗时、上传字节数、内存及显存 |
| 待冻结预算 | 世界场景、编辑频率、首次加载时间、内存和显存上限；目前没有足够数据给出可信硬阈值 |

P95 表示 95% 的样本不慢于该数值；P99 关注更少见的慢帧。不能仅用平均 FPS 宣称不存在卡顿，也不能删除编辑操作产生的慢帧改善结果。采集期间的外部干扰需记录，必要时整轮重测。

当前世界日志里的 seed 尚不能完整重放生成结果；先解决场景可重复性，再进行优化前后对照。原始程序的短暂启动观测不能充当此处的性能基准。

## 文档与学习交付

采用中文技术文档、英文代码标识符。工程文档和学习说明跟随模块交付，至少包括设计理由、数据流、所有权、调用入口、测试与限制。

针对当前知识基础，学习说明重点放在：单线程正确性如何建立、后台任务为什么不能共享任意可变数据、CPU/GPU 如何交接资源、固定步长模拟与渲染帧的关系，以及如何用测量而非猜测定位瓶颈。

首个可玩版本之后再选择深入优化方向，不提前承诺必须采用某一种 ECS、线程池、网格算法或渲染特性。
